⚡ CO.2 — CHOOSE AN APPROPRIATE PROGRAMMING SOLUTION TO REDUCE COMPLEXITY
OFFICIAL CO.2 BENCHMARK & ARCHITECTURE

Problem Statement: Multi-agent four-way traffic arbitration with heterogeneous vehicle classifications, dynamic emergency overrides, and headway safety interlocks can rapidly devolve into an unmaintainable "God Object" with exploding cyclomatic complexity ($M \ge 18$) if implemented using naive procedural branching. The Chosen Solution: A decoupled Object-Oriented architecture leveraging Polymorphic Dynamic Dispatch, Single Responsibility Principle (SRP), and dedicated algorithmic data structures (FIFO Queue + Hash Table), reducing cyclomatic complexity by 83% and achieving $O(1)$ constant-time lookup and queue buffering.

SOLUTION A: NAIVE PROCEDURAL APPROACH HIGH COMPLEXITY (ANTI-PATTERN)
  • Monolithic Function: Single 150+ LOC procedure with deeply nested if-else ladders.
  • High Cyclomatic Complexity: $M = 18$ independent execution paths requiring 18 tests.
  • Scattered Globals: Vehicle state held in parallel arrays without access encapsulation.
  • Linear Search Overhead: Iterates through all lanes in $O(N)$ time per cycle.
  • Fragile Extensibility: Adding 1 new vehicle type requires modifying 6 switch/if blocks.
SOLUTION B: CHOSEN MODULAR OOP + DATA STRUCTURES REDUCED COMPLEXITY (OPTIMAL)
  • Decoupled Hierarchy: Vehicle, EmergencyVehicle, TrafficSignal, TrafficLane.
  • Low Cyclomatic Complexity: $M = 3$ for master arbitration; $M = 1$ per leaf method.
  • Virtual Dynamic Dispatch: Priority score computed polymorphically with zero branching.
  • Constant-Time Operations: $O(1)$ Hash Table key lookup and $O(1)$ linked FIFO queue.
  • Open/Closed Principle (OCP): New vehicles added via simple inheritance with 0 edits to controller.

int calculatePriorityProcedural(int type, int emerg, int wait) {
    if (emerg == 1) {
        if (type == 1) return wait + 100;      // Ambulance

    }
}

// Chosen OOP Solution (Open/Closed Principle)
class Vehicle {
public:
    virtual int calculatePriority() const { 
        return waitTime; // Normal
    }
};

public:
    int calculatePriority() const override {

    }
};

✦ ARCHITECTURAL COMPLEXITY REDUCTION & MODULAR DESIGN
ENGINEERING METRICS
1. Single Responsibility & Separation of Concerns

The system decomposes traffic into distinct classes: Vehicle (state & physics), TrafficSignal (lamp states & interlocks), TrafficLane (headway buffering), and TrafficController (arbitration). No monolithic god-objects.

2. Open / Closed Extensibility

New vehicle classifications (e.g. VIPConvoys, PoliceInterceptors) are added by simply inheriting from Vehicle and overriding calculatePriority(), requiring zero modifications to the core arbitration loop.

ALGORITHMIC COMPLEXITY NOTE: Arbitration scan operates in $O(L \cdot V)$ time where $L=4$ lanes and $V$ is vehicles per lane. OOP encapsulation cleanly decouples time complexity from system maintenance overhead.
